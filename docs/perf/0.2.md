# Performance 0.2

Measured 2026-11-09 with `pnpm bench 0.2` (release build, nothing else started).

| What | Result | Budget | |
|---|---|---|---|
| Idle CPU (avg) | 0.02% | < 0.5% | ok |
| CPU with one item updating every second | 0.01% | < 0.5% | ok |
| Connect + hello to welcome | 3.5 ms | < 100 ms | ok |
| item.create until it is in the registry (median / worst of 30) | 0.3 / 1.2 ms | < 100 ms | ok |
| item.update (label) until it is in the registry (median / worst of 30) | 0.3 / 0.6 ms | < 100 ms | ok |
| Memory, private (bar + WebView2) | 58 MB | < 120 MB | ok |
| Memory, working set sum (reference) | 329 MB | counts shared pages | ok |
| Memory growth over 8 h | not measured | < 5 MB | |
| Click to menu / popover, cold start | from v0.3 | see budget file | |

- 7 processes counted (the bar and its WebView2 children), 12 logical cores.
- CPU: total over 76 s after 10 s of settling, divided by cores. The ticking row is the same with `examples/test-client` running (one label update per second).
- Latency is measured over the pipe with a minimal client: the time from sending the message until `debug.listItems` shows it. The UI sees it about one frame (16 ms) later, because `items-changed` is coalesced; the render time is the UI's.
- Machine: AMD Ryzen 5 7430U with Radeon Graphics, 15 GB RAM.
