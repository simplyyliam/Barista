# Performance 0.9

Measured 2026-11-19, Windows 11, AMD Ryzen 5 7430U (12 logical cores), 15 GB RAM.

**`pnpm bench 0.9` was not run for this PR.** It needs a release build and refuses to start while a bar is
running, and the dev bar was in use. Run it before merging and paste the table here. What was measured instead:

## Cost of one script run (median of 4, process CPU time and wall time)

| Script | Wall | CPU | Sensible interval |
|---|---|---|---|
| `clock.10s.mjs` (node) | 169 ms | 125 ms | 2 s and up |
| `hello.30s.py` (py launcher) | 151 ms | 31 ms | 2 s and up |
| `system-monitor.5s.ps1` (Windows PowerShell 5.1) | 1 763 ms | 1 547 ms | 5 s and up |

- PowerShell is the expensive one. Measured: `Get-CimInstance Win32_Processor` 1.1 s, `Get-Counter` 2.4 s,
  `Get-PSDrive` 0.18 s, `Get-Process` 0.2 s, a `try/catch` around `TotalProcessorTime` for every process 3 s.
  The example uses `.CPU`, .NET `ComputerInfo` and `DriveInfo` (1.7 s in total, down from 4.8 s).
- Five scripts at 10 s therefore cost roughly 5 x 0.13 s of CPU (node) per 10 s: about 0.1% of the machine.
  Five PowerShell scripts at 10 s cost about 5 x 1.5 s per 10 s: about 6% of one core, so use `.py` or
  `.mjs` for anything that runs often (the v0.8 first-party system monitor is the cheap version).
- Idle with no scripts: the runner is one parked thread (the folder watcher, `WaitForSingleObject`) and
  idle tokio tasks, no polling. Not re-measured with the bench; expect the v0.8 numbers.
- No extra Barista process: the runner is inside the bar. Only the scripts' own short-lived children appear.

## Checked live (dev bar, `%APPDATA%\Barista\scripts`)

- Sleeping forever, 10 MB of output, exit 1, binary output, and a script with a grandchild: each shows the
  error state, and no `node.exe` is left running afterwards (the grandchild was killed with its tree).
- Renaming `clock.10s.mjs` to `clock.1s.mjs` changed the timer with no restart and no new trust prompt.
- Editing a trusted script turns its item untrusted and stops its runs. Deleting a file removes its item.
